## 1. 用户要求原文摘要（按事项）

1. 动作库中「参数文字点击」改名为「参数文字动作」；但随后事项 1/2 进一步要求：**参数不属于动作库**，回退/删除当前动作库「参数」相关内容（`param_click_text`/`param_wait_text`/`param_long_press_text` 等预设）。
2. **参数也是素材的一种**，不属于动作库：参数是“使用端可随时更改识别文字”的素材类型；其初始识别区域为空，与普通 OCR 素材只有这些区别。为语义更准确，**“参数”更名为「使用端OCR文字配置项」**（用户允许换成更贴切的名字）。
3. **素材行识别逻辑**：选中素材时显示“识别区域/操作区域”；点「识别」返回**所有满足阈值的真实识别区域**；后端函数返回所有候选区域及评分。素材行设置里的所有测试动作在演练时测试所有候选；真实点击测试可选择任意候选区域，如点测下拉显示所有候选序号+评分。
4. **量尺功能**：相对偏移编辑时，测量画面两点直线距离，**直接复制到剪贴板**。
5. **操作区域三方式 + 递归套娃**：
   - 1 默认现有概念/功能（不要重复造轮子）
   - 2 素材库素材自带操作区域（单一匹配/多候选匹配；多候选选距离最近）
   - 3 相对偏移
   - 递归：素材1 的操作区可选择“当前素材操作区域 / 相对偏移 / 素材库所有素材（可搜索/候选）”；选素材2 后继续出现同样选择，直到“当前素材区域/相对偏移”收尾。**必须防互相递归死循环**。
   - 运行语义：依次识别素材1→素材2→…，最后对末端操作区域执行动作；中间任一素材未出现 → **不执行后续并报错**（该步骤失败）。这样动作库无需复杂参数交互。
6. **废弃操作区域“与真实识别区域有无交集”两种状态**：用户怀疑当前代码本来就有“识别不到则退回全图识别、操作区域随真实识别区域相对位移”的实现，若有则两状态无意义；请确认并**删除**。
7. 另：参数是固定的，选择动作时不应再选参数（参数归配置管）；选择“参数文字动作”后出现的选项按语义应是**操作区域划定 + 具体动作**。操作区域只有：1 参数真实识别区域；2 素材库素材自带操作区域（单一/多候选最近）；3 相对偏移。

## 2. 目标概念模型（建议）

- **素材库**：1) 普通素材（template/region/collection/OCR 素材）；2) **使用端可变文字素材**（原参数：kind 建议 `ocr_var`/`ocr_runtime_text`，初始识别区域为空；使用端可随时改识别文字；无固定 ROI 时由使用端/任务引用处提供区域或初始化时再填）。
- **动作库**：只保留“动作”（点击/长按/拖动/曲线滑动/识别/等待/控制流…）；**不再有参数动作预设**。
- **动作配置**：选动作 → 指定“识别/操作目标”（素材或参数文字素材）→ 指定“操作区域”三方式（真实识别区域 / 素材自带操作区域（单/多候选最近）/ 相对偏移）。
- **操作区域递归链**：操作区引用另一个素材 → 该素材识别成功后才继续；链末端必须是“当前素材区域/相对偏移”；循环引用必须拒绝（图环检测或 visited 集合）。
- **素材测试**：素材行「识别」返回候选列表 `[{index, rect, score, op_rect?}]`；「点测」可选择候选。

## 3. 后端/API 草案（待细化）

- 素材操作区域解析：`operation_region` 支持链式引用（`{mode:"asset", asset:..., op_region:{...}}`）或素材库内维护操作区配置；需防环。
- 量尺：前端画布两点测量 + 复制 `dx,dy,dist`；不涉及后端（或可输出坐标）。
